# Proliferate Documentation

Start here before changing the repository. These documents make ownership,
current behavior, and contributor procedures discoverable without relying on
chat history.

## Authority

Documentation artifacts have distinct jobs:

| Artifact | Meaning | Authority |
| --- | --- | --- |
| Current codebase document | Describes behavior and ownership on `main`. This is the default when no other status is declared. | Operating law for its area. |
| System spec | One document per system under `codebase/systems/**`, in the nine-section anatomy (Purpose, Owned state, Public surface, Consumes, Laws, Emits, Fences, Code map, Proof). Every source file belongs to exactly one spec's code map. | Operating law for that system; a change is filed against the spec that owns the code. |
| Target contract | Describes an accepted destination that is not fully current. It must be labeled `Status: target` and name the current gap. | Governs only an explicitly assigned migration. |
| Procedure | Describes how to perform and verify a current task under `guides/**`, `specs/TESTING.md`, and `specs/TESTING/**`. | Operating law for that task. |
| Generated reference | Reproducible output under `specs/GENERATED/**`. | Evidence generated by its named owner; do not hand-edit. |
| Delivery specification | Founder-approved intent for one PR, stored in the repository under `delivery/<program>/delivery-spec-<slug>.md`. It is a frozen delivery artifact, not canonical documentation: it never joins `specs/**`; once its PR merges it is superseded as authority by git history, and the file under `delivery/**` is retained as a frozen archive. | Governs that PR's intended delta. |

Chats are working context, not authority. Git history is the archive; completed
plans and mutable rollout status do not belong in the canonical read path.

If a delivery specification contradicts a current area document, stop and
report the exact contradiction. Do not silently redefine either one.

## System Index

One line per system spec. A spec marked *target* describes an accepted
destination and names its current gap; a spec marked *superseded* is a
bannered pointer kept for inbound links and owns nothing. Add a new system as
one line in its plane's list; the lists are append-only by system name.

## Read Order

1. Read [`AGENTS.md`](../AGENTS.md) for the source-area router.
2. Find the owning system in the [System Index](#system-index) and read its
   spec; it is the authority on behavior.
3. Read the relevant structure document before editing that source area.
4. Use [`codebase/README.md`](codebase/README.md) to find the shared capability
   a system consumes.
5. Use [`../guides/README.md`](../guides/README.md) for task procedures.
6. Read the frozen delivery specification for the intended PR delta.

## Writing Rules

Style and structure expectations for every document live in
[authoring.md](authoring.md); the rules below govern placement and
authority.

- Describe ownership, behavior, failure handling, and proof directly.
- Put source organization in the owning `specs/<owner>/` document
  (`anyharness/`, `server/`, `frontend/`, or a thin owner's single file);
  `codebase/structures/README.md` is only the pointer index to them.
- Put reusable capability contracts in `codebase/platforms/**`.
- Put complete product, runtime, and engineering systems in
  `codebase/systems/**`, one spec per system in the nine-section anatomy; a
  feature is a section of its owner's spec, never a spec of its own.
- Put task procedures in the repository-root `guides/**`; do not duplicate
  system architecture there.
- Label target material explicitly and state how it differs from current code.
- Keep implementation progress in the PR or delivery tracker, not in canonical
  documentation.
- Update current documentation in the same PR that changes its behavior.
- Keep unapproved proposals and founder planning outside the permanent
  repository documentation path until they are accepted as a current or target
  owner.
- Store founder-approved delivery specifications in the repository at
  `delivery/<program>/delivery-spec-<slug>.md`, one file per intended PR.
  `delivery/**` is a frozen artifact tree: freeze the file before
  implementation starts, never hand-edit it afterward except to record a
  founder re-ruling, and never move it into `specs/**`.
- Use [`../scripts/check_docs.py`](../scripts/check_docs.py) after documentation
  changes.
