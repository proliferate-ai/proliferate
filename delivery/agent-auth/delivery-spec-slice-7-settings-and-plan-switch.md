## Intent

One slice makes the shipped UX match the ruled system. The settings pane becomes the v2 design — exactly one route visibly in use, multi-plan Claude logins with live meters, a flat models list, install as an in-structure row. The composer gains plan-usage rings and a popover that shows the windows, switches plans, and offers to restart the sessions left behind. The ruled deadwood is deleted. Nothing here invents state: every pixel reads the slice-3 presentation package, slice-4 samples, or the two small data enablers below.

**C. The composer plan switch.**
- *Data enabler 1 (server)*: `agent_api_keys` gains nullable `seat_email` and `seat_plan` columns; the mint flow threads its existing sheet fields into them; the wire type gains `seatEmail`/`seatPlan`. One alembic migration on the current head (`check_migration_heads.py` before finalizing); no backfill — existing seats render the title fallback.
- *Data enabler 2 (runtime)*: the contract `Session` gains `serving_seat_id` (nullable — populated from the live actor's existing field, `None` for non-seat routes), through the serializer, fixture, and generated SDKs. This is read-only exposure of state the runtime already holds.
- *The switch is not a new mutation*: clicking a plan writes the **existing selection PUT** pinned to that seat's `api_key_id` (the NULL-key row is the rotation pool; a pin implies rotation off and the popover mirrors that honestly; the rotate toggle restores the pool row). The pending → applied ack that already drives `useAuthRestartOffer` therefore fires for free; `matchRunningSessions` gains an optional `servingSeatId` filter (fed by enabler 2) so the count is exact — sessions still holding the previous seat, not every session of the harness.
- *The offer, composer-shaped*: the popover renders the same offer state as the ruled **inline row** — "N sessions are still on the previous plan." + small secondary Restart (loading while relaunching, row gone on completion), backed by the existing `restartSessionsOnNewAuth` (dismiss → restore → resume, transcripts kept). Settings keeps the modal; two surfaces, consciously two shapes.
- *Presentation*: **PlanUsageRing** (net-new SVG) — concentric arcs, outer 5h / inner 7d, 20px in the composer control (stroke 2) and 24px in rows, arcs from 12 o'clock (rotate −90), round linecap, minimum visible arc 2%, 300ms ease on dasharray for live updates; track `muted-foreground` @25%, value `foreground` switching to `warning-foreground` at ≥75% per ring independently. The 75% threshold becomes **one exported constant** consumed by the ring and `HarnessSeatUsageMeter` both. The composer control is a `ComposerControlButton iconOnly` rendered **only when the applied route is a seat** (`useHarnessStatus().applied.kind === "seat"`), tooltip naming the email and both windows, sitting left of the context ring.
- *The popover*: 360px, anchored above the composer — header ("Claude Plans" + updated-ago), two labeled window bars (binding window emphasized, "resets \<time\>" right-aligned, "N% left"), the plans list (mini ring, email, "\<plan\> · 5h N% · 7d N%", trailing serving-dot or switch), the inline restart row post-switch, and a "Manage plans" footer routing to the harness settings pane. The context ring stays session-scoped (single arc, unchanged geometry); its popover is rebuilt to the 300px card (header, thin bar, Used / Free space / Session cost). One popover open at a time — the existing radix outside-dismiss behavior, no new coordinator.
- *Data*: `useSeatUsage`/`useRefreshSeatUsage` as-is — popover open triggers the refresh mutation (pane-open-poke parity); rings animate on new samples. **No new poll loop anywhere.**
